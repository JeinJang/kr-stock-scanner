# analyze-thesis 스킬 설계

- **작성일:** 2026-07-01
- **상태:** 설계 승인 대기
- **목적:** 특정 투자자의 분석 관점(사이클·촉매·밸류체인 중심의 미래 지향 정성 논거)을 코드화한 스킬을 만들어, 기존 정량 스킬 `analyze-stock`을 보완한다.

## 배경

세 건의 투자 노트(동성화인텍 · 한화엔진 · ESS/Fluence)를 분석한 결과, 한 투자자의 일관된 분석 스타일을 도출했다. 요지는 다음과 같다.

- **탑다운 테마 + 바텀업 실적의 하이브리드.** "전력·에너지 전환" 및 "탈중국 공급망 재편" 메가트렌드에 베팅하되, 개별 종목은 실적으로 검증.
- 반복 사용하는 프레임: 매출 P×Q 분해, 수주잔고·리드타임·빈티지별 마진, OPM 궤적과 드라이버, 사이클 지속성(구조적 vs 순환적), 캐파-수요 수급, 촉매/모멘텀, 정책/지정학, 매크로 민감도, Forward PER + 글로벌 피어, 밸류체인 내 최적 포지션, 1차 소스(경쟁사/고객사/인접산업 컨콜) 삼각검증, 리스크 명시.

기존 `analyze-stock`(`.claude/commands/analyze-stock.md`)은 철저히 DB 기반·정량·과거 회계 스냅샷 분석이며 "외부 지식 금지, 투자 추천 금지"가 원칙이다. 이 투자자의 방법은 상당 부분 DB에 없는 미래 정보(IR/컨콜/가이던스/정책/피어 밸류에이션)에 의존하므로, 별도의 **정성·미래 지향** 스킬로 만드는 것이 상호보완적이다.

## 확정된 설계 결정

1. **모드 2개** — 종목 논거 모드 + 테마 밸류체인 수혜주 발굴 모드. 인자로 분기.
2. **데이터 소스** — DB + 웹 리서치 하이브리드. 모든 결론에 근거 등급 태그(`[DB]`/`[웹:출처]`/`[추정]`).
3. **결론 성격** — 논거 기반 방향성 견해 허용. 단, 근거·가정·리스크 명시 필수. "매수/매도하세요" 단정 표현 금지.
4. **정량 토대** — 종목 모드는 `analyze-stock`의 DB 쿼리(연도별 손익 트렌드, PER/PBR/ROE, 섹터/시장 중앙값, 연관기업 엣지)를 재사용.
5. **결측 데이터 자동 복구** — 비용에 따라 차등(아래 에러 처리 참조).

## 구조

프로젝트 스킬로 구현한다(SKILL.md는 얇게, 방법론은 references로 분리).

```
.claude/skills/analyze-thesis/
  SKILL.md            # 절차, 모드 분기(종목/테마), 출력·저장·품질 가드 규칙
  references/
    lens.md           # 12개 분석 렌즈 체크리스트 (두 모드 공유)
    stock-mode.md     # 종목 모드 상세 절차 + 보고서 템플릿
    theme-mode.md     # 테마 모드 상세 절차 + 보고서 템플릿
```

**호출:**
- `/analyze-thesis <ticker>` — 종목 모드
- `/analyze-thesis theme:<키워드>` — 테마 모드

## 분석 렌즈 체크리스트 (`references/lens.md`)

| # | 렌즈 | 핵심 질문 | 소스 |
|---|---|---|---|
| 1 | P×Q 분해 | 매출 성장이 물량(Q)인가 단가(P)인가, 각각 지속되나 | DB + 웹 |
| 2 | 수주잔고·리드타임 | 잔고 규모, 매출인식 시차, 빈티지별 마진 개선 | 웹 |
| 3 | OPM 궤적·드라이버 | 마진 추이 + 변동 원인(원재료/믹스/고정비/판가) | DB + 웹 |
| 4 | 사이클 지속성 | 구조적 수요인가 순환적인가, 과거 사이클 대비, 피크아웃 신호 | 웹 + 판단 |
| 5 | 캐파 vs 수요 수급 | 과잉 증설 우려 검증 (자사·경쟁사·전방 캐파 대조) | 웹 |
| 6 | 촉매·모멘텀 | 신규 발주/수주/정책 이벤트, 타이밍 | 웹 |
| 7 | 정책·지정학 | 관세, 정부 정책, 규제 테일윈드 | 웹 |
| 8 | 매크로 민감도 | 환율·원자재·전방 가격의 손익 탄력 (정량화) | DB + 웹 |
| 9 | 밸류에이션 vs 피어 | Forward PER(사이클 이익) + 글로벌 피어 멀티플, 리레이팅 여력 | DB + 웹 |
| 10 | 밸류체인 포지션 | 셀→소재→부품 중 리스크/리워드 최적 자리 | DB + 웹 |
| 11 | 1차 소스 삼각검증 | 경쟁사·고객사·인접산업 컨콜로 교차확인 | 웹 |
| 12 | 리스크 명시 | 논거를 깨뜨릴 요인 별도 섹션 | 종합 |

**적용 규칙:**
- 종목 모드는 12개 렌즈 전부 시도하되, 근거를 못 찾은 렌즈는 "근거 부족"으로 명시(추측 금지).
- 각 렌즈 결론에 `[DB]`/`[웹:출처]`/`[추정]` 태그.
- 테마 모드는 4·6·7·10 렌즈를 중심으로 적용.

## 종목 모드 (`references/stock-mode.md`)

**절차:**
1. 티커 확인 — 없으면 6자리 티커 요청.
2. 정량 토대 확보 — `analyze-stock` SQL 재사용(연도별 손익 트렌드, PER/PBR/ROE, 섹터/시장 중앙값, 연관기업). 신선도 경고 규칙 동일.
3. 웹 리서치 — 렌즈 2·4·5·6·7·9·11 보강. IR/실적/수주공시/경쟁사·고객사 코멘트/정책/글로벌 피어 멀티플. 각 발견에 URL·날짜 기록.
4. 12개 렌즈 적용 — 근거 태그 부착.
5. 논거 종합 — 방향성 견해 + 핵심 논거 3가지 + 이를 깨뜨릴 리스크.
6. 파일 저장 — `docs/analysis/{TICKER}_{NAME}_thesis_{YYYY-MM-DD}.md`. 채팅에 경로 링크.

**보고서 섹션:** 한 줄 논거 → P×Q 분해 → 실적 궤적 & 마진 드라이버 → 수주잔고 & 미래 실적 가시성 → 사이클 & 수급 → 촉매 & 정책 → 밸류에이션 vs 피어 → 밸류체인 포지션 → 리스크 → 근거 등급 & 출처. 각 헤더에 근거 태그.

## 테마 모드 (`references/theme-mode.md`)

**절차:**
1. 테마 정의 — 인자를 받아 범위 확정, 모호하면 1-2개 질문.
2. 메가트렌드 & 수혜 구조 (렌즈 4·7) — 수요 성장 근거 + 정책 촉매. "성장 + 점유율 이전" 성립 여부.
3. 밸류체인 매핑 (렌즈 10) — 완제품→중간재→부품/소재 단계 분해, 각 단계 한국 상장사 후보를 연관기업 DB + 웹으로 나열.
4. 노드별 스크리닝 — 각 후보의 시총·매출비중·수주가시성·경쟁강도 조회, 리스크/리워드 태깅.
5. 최적 자리 도출 — 판단 기준 적용(빅캡은 테마 탄력 약함, 수주 실적 있는 벤더 우선, 매출 비중 높을수록 순수 노출). 1-3개 우선 후보 + 이유.
6. 파일 저장 — `docs/analysis/themes/{테마슬러그}_{YYYY-MM-DD}.md`. 채팅에 경로 링크.

**보고서 섹션:** 메가트렌드 & 수혜 구조 → 밸류체인 지도(표) → 노드별 리스크/리워드 → 최적 포지션(우선 후보) → 리스크 & 출처.

**두 모드 연결:** 테마 모드가 도출한 우선 후보는 `/analyze-thesis <ticker>`(종목 모드)로 심화 가능하다고 보고서 말미에 안내.

## 에러 처리 / 결측 데이터 자동 복구

- **가벼운 것 → 확인 없이 자동 실행**
  - 연관기업 데이터 없음 → `python -m src.related.cli show <ticker>` (단일 종목, 사업보고서 1건 + GPT 추출 1회).
  - 연도별 시총 오래됨 → 단일 종목 fresh 갱신(analyze-stock 인라인 방식 재사용).
- **무거운 것 → 확인 후 자동 실행**
  - 펀더멘털 없음 → `fundamentals.cli run`은 KOSPI/KOSDAQ 전 종목 파이프라인(수 분~수십 분, API 대량 호출). "지금 돌릴까요?" 확인 → 승인 시 실행, 거절 시 "정량 토대 결측" 경고와 함께 웹 렌즈 중심으로 부분 진행.
- 자동 실행 후에도 데이터가 안 채워지면 원인을 보고서에 명시.
- **신선도 경고** — `fundamentals_metrics.as_of_date > 30일`이면 상단 경고(기존 규칙 재사용).
- **웹 근거 못 찾음** — 해당 렌즈 "근거 부족"으로 명시.
- **동일 날짜 파일 존재** — 덮어쓰기 전 사용자 확인.

## 품질 가드 (SKILL.md에 명문화)

- 모든 렌즈 결론에 `[DB]`/`[웹:출처]`/`[추정]` 태그 필수.
- 웹 인용은 URL + 날짜 기록.
- 방향성 견해 허용하되 단정 매수/매도 표현 금지, 반드시 리스크 섹션과 짝.
- 외부 수치와 DB 수치 충돌 시 양쪽 병기 + 출처 명시.

## 테스트 / 검증

- 스킬은 프롬프트(SKILL.md + references)라 단위테스트 대상 아님.
- **수동 검증 1케이스:** DB 보유 종목 1개로 종목 모드를 1회 실행해 12개 렌즈·근거 태그·파일 저장 규칙 준수 확인.
- SKILL.md frontmatter(`name`, `description`)가 `/analyze-thesis`로 정상 노출되는지 확인.

## 범위 밖 (YAGNI)

- `analyze-stock` 자체 수정(이 스킬은 그 SQL만 재사용, 원본 불변).
- 웹 리서치 결과의 DB 영구 저장(이번 범위는 보고서 산출까지).
- 종목/테마 외 추가 모드.
